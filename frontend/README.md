# Crowd DJ Frontend

Crowd DJ is a collaborative music-room application where a host and guests build and manage a shared music queue in real time. This folder contains the React frontend, which communicates with a Node.js/Express backend and a PostgreSQL database through a REST API. The frontend provides the user interface for authentication, party creation and joining, music discovery, queue management, playback controls, comments, and profile management. It integrates with the backend to synchronize party state across users while retrieving song information from the iTunes Search API.

## Technology

- React
- Vite
- React Router
- JavaScript
- CSS
- React Context API
- REST API
- JWT Authentication

## Run locally

```bash
cd frontend
npm install
npm run dev
```

The frontend communicates with the backend through the API base URL defined in the environment variables.

Create a `.env` file if one does not already exist:

```env
VITE_API_BASE_URL=http://localhost:3001/api
```

If your backend is running on another host or port, update the value accordingly.

To verify that the project builds successfully:

```bash
npm run build
```

## Routes

- `/` redirects to `/home`
- `/home` displays the current party, queue, and recommended songs
- `/login` allows users to register and log in
- `/profile` displays the authenticated user's profile
- `/create-party` allows authenticated users to create a new party

## Current Behavior

Users can register and log into their accounts using JWT-based authentication. After logging in, users may create a new party or join an existing party using a room code generated by the host.

Within a party, users can browse recommended songs or search the iTunes catalog, then add songs to the shared queue. Album artwork and 30-second previews are retrieved directly from the iTunes Search API and displayed within the interface.

The host has exclusive control over playback. Hosts may:

- Play and pause the current song
- Skip the current song
- Automatically advance to the next song when a preview finishes

Guests may:

- Join parties using the room code
- Browse the queue
- Add songs (when permitted)
- Comment on songs
- Join the synchronized audio playback

Browser autoplay restrictions require guests to manually press **Join Audio** before music can begin playing.

The frontend communicates with the backend through REST API endpoints for:

- Authentication
- Party management
- Song queue management
- Playback synchronization
- Comments
- Voting
- Music search

Authentication tokens are stored locally and automatically included in authenticated API requests. Playback information, queue updates, and current song information are synchronized with the backend to ensure every participant views the same shared party state.

## Notes

The frontend is designed to remain independent of the underlying database implementation. All persistent data—including users, parties, songs, comments, votes, and playback state—is managed by the backend. The frontend is responsible only for rendering the interface, sending API requests, and displaying the current application state returned by the server.
